# 雨中便利店街角 · 微缩模型

一个可以用鼠标拖拽、旋转、缩放观看的 **三渲二日式便利店街角**。
画面主体是可以自由把玩的微缩模型；底部是一块**时间 / 天气两维独立**的轻量控制台。

Three.js + TypeScript + Vite。**所有几何与贴图都是运行时程序化生成的**：
没有 GLTF/GLB 模型文件，没有贴图文件，没有二进制资源。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器
npm run build      # 生产构建（输出到 dist/）
npm run preview    # 预览构建产物
npm run typecheck  # 类型检查
```

需要 Node.js ≥ 22.12（Vite 8 的要求；GitHub Actions 里也用 Node 22）。

## 操作

| 输入 | 行为 |
| --- | --- |
| 左键拖拽 | 旋转视角 |
| 滚轮 | 缩放（8–60 m） |
| 右键拖拽 | 平移 |
| 触屏单指 | 旋转 |
| 触屏双指 | 缩放 / 平移 |
| `1`–`3` | 白天 / 黄昏 / 夜晚 |
| `4`–`6` | 晴 / 雨 / 雪 |
| `T` / `W` | 循环时段 / 循环天气 |
| `←` `→` / `↑` `↓` | 在当前分组内移动 |

打开页面后，先是一段**代码开场动画**：脚本逐字敲出 `buildWorld({ time: 'day', weather: 'rain' })`，敲完后两扇门向左右滑开，露出背后正在组装的模型。随后模型会**从地面开始逐层组装**：底座 → 铺装 → 建筑外壳 → 店内陈设 → 屋顶设备 → 街道家具 → 小道具，最后招牌亮起。

开场动画约 5 秒，**点击 / 任意按键可立即跳过**；`?intro=0` 只跳过开场字幕、保留模型组装，`?instant=1` 两者都跳过（截图与自动化测试用）。

## 时段与天气

**时间**（白天 / 黄昏 / 夜晚）和**天气**（晴 / 雨 / 雪）是两个完全独立的维度，
共 9 种组合。底部控制台把两者拆成两条分段轨道，各自有图标、标题和选中态：

```
┌──────────────────────────────────────────────┐
│ ● 环境   时间 [白天][黄昏][夜晚]  │  天气 [晴][雨][雪] │
└──────────────────────────────────────────────┘
```

- 桌面单行、手机双行（388px 竖屏也能完整放下），贴在底部居中
- 默认半透明、悬停/聚焦完全不透明，尽量不抢画面
- **时间只改光与色，天气只改降水与空气**：
  - 时间：主光 / 天光 / 补光、雾的基准、天空渐变、曝光 / 饱和 / 暗角、bloom 基准、店内与招牌亮度
  - 天气：雨量、雪量、地面积水、雾的倍率与灰度、云层遮光、星空通透度
- 因此「白天 + 雨」「黄昏 + 雪」「夜晚 + 晴」都成立；切时间不会让正在下的雨停下，
  切天气也不会重置积雪
- 状态单向流出：UI 只发指令，高亮由 `Environment.onChange` 统一回灌，不会脱节
- 在控制台上拖拽**不会**旋转相机（事件已隔离）
- 键盘：`1`–`3` 切时段，`4`–`6` 切天气，`T` / `W` 循环，`←` `→` / `↑` `↓` 在同组内移动
- 切换时段/天气时页面标题、`theme-color` 和 `html[data-time]` / `html[data-weather]` 同步更新

```bash
?time=day&weather=clear    # 白天晴天
?time=dusk&weather=snow    # 黄昏下雪
?time=night&weather=rain   # 夜晚下雨
?time=day&weather=rain     # 白天 + 雨（默认，也是这个作品的主调）
?intro=0                   # 跳过代码开场字幕，保留模型组装
?weather=snow&instant=1    # 雪立刻铺满（截图 / 调试用）
```

```js
__konbini.env.set({ time: 'dusk' })        // 只换时段，1.5s 平滑过渡，天气不变
__konbini.env.set({ weather: 'snow' })     // 只换天气，时段不变
__konbini.env.cycleTime()                  // 白天 → 黄昏 → 夜晚 → 白天
__konbini.env.toggleWeather()              // 晴 → 雨 → 雪 → 晴
__konbini.env.getSnow()                    // 当前积雪量 0..1
__konbini.env.details()                    // 雨量 / 雪量 / 湿度 / 星空 / 光照等合成结果
```

### 雪

切到**雪**之后：

- **飘雪**：1800 个实例化粒子，圆形软边、慢速下落、双频横向摇摆（只落不飘会像白点雨）；
  切到雪天的 1.5s 过渡里就会显形，**不等地面积满**
- **积雪**：地面、人行道、屋顶、雨棚、贩卖机顶、邻楼顶各铺一层薄雪，
  约 **12 秒**从 0 线性长到 **4cm** 后**停住**，不会再变厚；切走后约 5 秒融化；
  **切时段不会重置积雪**，雪会继续长或化
- 雪天光照转为漫射：方向光压到 45%、环境光提到 140%、饱和度降到 82%，
  雾更浓更冷白，bloom 收一点避免雪面高光过曝

厚度上限有两道保险：`DEFAULT_MAX_DEPTH = 4cm`，再加 `MAX_HARD_DEPTH = 4.5cm` 的最终夹取 ——
即使某个面的厚度系数写大了也不会突破。

### 星空

星空可见度 = **时段基准 × 天气通透度**：

- 夜晴 `1.0`；夜雨 `0.12`、夜雪 `0.24`（云层遮住大部分）
- 黄昏晴 `0.26`，黄昏雨/雪只剩一点点
- 白天恒为 `0`
- 天空渐变始终保留（不再和星星共用一个 opacity）；白天是渐变蓝天，夜晚是暗天 + 星点

切到晴天时，雨丝、屋檐滴水、玻璃雨痕、体积光锥、飘雪、雨滴涟漪和湿地反光会**按天气**
淡出/隐藏；切到雨天时再淡入。晴天与雨天地面的差别不再靠"时段"间接决定。

## 美术实现

**三渲二的核心是 `MeshToonMaterial` + 色阶渐变贴图。** 本项目用了三套色阶：

| 色阶 | 档数 | 用途 | 为什么 |
| --- | --- | --- | --- |
| `RAMP_MAIN` | 4 | 默认 | 硬边色阶，赛璐璐的骨架 |
| `RAMP_SMOOTH` | 12 | 地面、人行道 | 4 档色阶在地板上会被点光切出一圈圈同心色阶，像渲染 bug |
| `RAMP_INDOOR` | 6（0.46–0.86） | 店内一切 | 上限低避免死白，下限高才能在隔玻璃 + 叠雨的情况下看清货架 |

**轮廓线**：自建后处理管线做**深度边缘检测**（5 点拉普拉斯 + 近 / 远距离淡出）。
不用 `OutlineEffect`，因为它会替换材质，与 `InstancedMesh` 和自定义 `ShaderMaterial` 冲突。

**后处理顺序**：场景（含深度纹理）→ UnrealBloom 叠加 → 描边 + split toning + 暗角 + sRGB → 屏幕。

**发光体质**：招牌、灯箱、贩卖机面板用 `MeshBasicMaterial` 且允许颜色 > 1，交给 bloom 糊开。

### 关键设计决策

**总平面只有一个来源。** 所有坐标从 `scene/layout.ts` 读，任何模块都不硬编码尺寸。

**入场动画结束后才合并静态几何。** 场景约 830 个 Mesh，加阴影 pass 后 draw call 到 1760，
合并后降到 **~770**（含信号灯新增的发光面片）。只处理 `MeshToonMaterial`，跳过 `InstancedMesh`、
发光体、玻璃、雨、雪和 `auto-door` 子树 —— 这些每帧都在动。

**商品用"包装贴图 + InstancedMesh"。** 每件商品不再是一个纯色方块：
薯片袋有品牌、口味、薯片插画、净含量和条码；盒装零食、罐装、瓶装、杯面各有自己的版式。
按品类/变体分 17 个 InstancedMesh，747 件商品仍然只有 17 个 draw call 级别的开销。
近看能读出 SKU，远看货架上是彩色包装而不是一排色块。

**灯光要少而准。** 店内只放 3 盏有分工的点光 + 1 盏冷柜冷色补光，而不是十几盏小灯平铺。

## 踩过的坑

记在这里，避免重复踩：

**点光源阴影会在人行道上糊出一块椭圆。** 点光阴影是 6 面立方体贴图，bias 稍有不合适就在
大平面上糊出一块发虚的深色区域。现在门灯**不开阴影**，投影全部交给方向光。

**贴墙放点光会切出半圆形亮斑。** 补光必须离墙面足够远，且 `distance` 要小。

**招牌光晕不能比招牌大太多。** 光晕是径向渐变平面，尺寸若比招牌高出一截会在招牌上方画出半圆"穹顶"。
另外**圆形衰减贴在长条平面上，四角会露出弧线** —— 必须按宽高比生成椭圆衰减（`glowSprite`，
用切比雪夫半径而不是欧氏半径，四角严格归零）。

**浅色平面被顶光打亮后会顶到色阶最高档。** 雨棚初版是奶白色，整块变成没有明暗的白板。
现在顶面中灰、底面深色，只靠边缘灯槽表达灯光。

**店内灯太多会把一切烧成白色。** 10 盏 `intensity=2` 的点光叠加直接推过 1.0。
现在 3 盏 + `RAMP_INDOOR`。

**湿地反光片的高度要分开。** 路面 y≈0、人行道 y=0.14。反射片统一放 0.024 会沉到人行道下面，
玻璃透出的暖光在地上完全没有倒影，画面会显得"干"。

**加法混合的贴图必须做椭圆遮罩。** 在 2:1 的贴图上用圆形渐变，左右边中点仍有约 27% 不透明度。

**道具会挡住主体。** 行道树、电线杆都曾经正好落在「相机 → 店角」的连线上。

**自动门的原点必须在门洞中心。** `doorRoot` 建在场景原点 x=0，而门洞中心在 x=0.95，
两扇门整体偏左，滑动时滑到门洞外面，看起来就是"门打不开"。另外滑动量要封顶。

**纯玻璃门看不出开合。** 门扇是透明玻璃 + 细边框，开门时画面几乎没变化。
现在每扇门玻璃上贴一条横向店铺信息带（`doorStickerTex`）。

**收银台的朝向要顺着"能看见"的方向摆。** 贴右墙时，外面正好是两台自动贩卖机，
从任何街角角度都被挡住。现在平行于正面玻璃、位于其后方。

**黄昏最容易"橙过头"。** 人行道砖底色本身偏红棕，暖光 + 暖 gain + 高饱和会把地面推到紫红。
现在暖光只给"光"不给"色"，色相由天空渐变承担，地面用冷蓝 fill 平衡。

**零件的"原点"要放在它真正接触地面的位置。** 电线杆的组原点原本在路面高度 `y=0`，
而杆体从 `CURB`（0.14）开始画 —— 整根杆凭空高了 14cm。

**有轮子的东西不能靠手算高度。** 自行车轮心 0.33、轮胎半径 0.346，胎底比组原点低 1.6cm，
整车陷进地砖。现在构建完用世界包围盒量一次真实最低点再抬起来。

**「时段」和「天气」不能共享同一批字段。** 旧版把 `rainDensity` 写进时段预设里，
于是「白天 + 雨」算出来的雨量是 0 —— 选了雨却不下雨；晴天里湿地反光和涟漪也一直开着；
星空可见度还拿 `signage` 当"夜晚程度"用。现在 `environment.ts` 拆成
`TIME`（光/色/雾基准）和 `WEATHER`（雨/雪/湿度/云/光照修正）两层，
`compose(time, weather)` 纯函数合成 9 种组合，UI 层也把两组做成独立 radiogroup。

**人行道挤出的高度不能 translate 两次。** `ExtrudeGeometry(depth=L.curb)` 旋转后已经在
`0..0.14` 之间，再 `translate(0, L.curb, 0)` 会把顶面抬到 0.28。自行车、垃圾桶、护栏、
信号灯全按 0.14 摆放，于是轮胎陷进路面 14cm；湿反光、门垫、人行道积雪也一起被埋掉。
现在顶面严格等于 `L.curb`，并加了「`sidewalk` 顶面 = 路缘」的断言。

**招牌的箱体和贴图必须共心。** `addBox` 的 y 参数是底边，而竖招牌的四张 face plane
以几何中心为原点。旧版箱体写 `yBottom = 0`，贴图却从 `-1.2..1.2`，箱体比贴图高 1.25m ——
贴图下半截悬在玻璃前，看起来就是"招牌下面有一截透明的"，还和檐口互相穿插。
现在箱体 `yBottom = -1.25`，上下金属收边、贴图、支架全部对齐；招牌整体抬到
1.30–3.90m，用两根支架挂到店角，底部不再露玻璃。

**货架不能是"实心盒子 + 藏在里面的商品"。** 面向玻璃的矮货架旧版先用一块
`x1-x0 × h × spanZ` 的实心盒体做柜身，再把商品放在盒体内部 —— 从街上只能看到
一块白板，商品完全不可见。现在只保留底座、两侧板、背板和顶板，正面敞开，
薯片/杯面直接对着玻璃。

**柜台不能只做一个大立方体。** 收银台旧版是 `span × 0.82 × depth` 的整块盒子，
从门口看是一块灰立方体。现在正面拆成四块嵌板 + 竖向分缝 + 拉手，加了踢脚散热口
和咖啡菜单板；近看能读成收银台，远看仍有完整的体块。

**招牌侧面的装饰条不能突出箱体。** 旧版在 +x 面挂了两根 `0.4 × 0.065` 的 trim 条，
伸出箱体 0.13m，从街上看像"招牌上插了两块黑色小方块"。现在删掉，招牌宽度严格
等于箱体 + 上下收边（0.54m），并有 `sign.w <= 0.58` 的断言兜底。

**商品贴图不能给 instanceColor 再乘一遍颜色。** 包装贴图本身带品牌色，
`instanceColor` 再乘一次会把红色薯片袋染成暗红/粉色。现在包装商品全部用白底
材质 + 贴图，颜色交给 Canvas；`InstancedMesh` 只负责矩阵。

**圆杆不能直接 `lookAt`。** `Object3D.lookAt` 把 local +Z 对准目标，而 `CylinderGeometry`
的长轴是 local +Y。旧版 `strut(..., round=true)` 也直接 lookAt，结果信号灯横臂变成一根
竖杆（几何包围盒 maxY 从 5.12 被拉到 5.70）、路灯臂/自行车车架也变成立着的圆片。
现在用 `setFromUnitVectors((0,1,0), dir)` 把圆柱轴真正对齐到 a→b。

**红绿灯不能只是"挂两个发光面片"。** 旧版行人灯离杆子 0.4m、没有支架，看起来浮空；
灯箱三颗灯全亮，没有遮光罩；杆子还立在路口中间 / 横臂正对店面。
现在信号灯是一套完整构件：杆脚在人行道转角 → 横臂伸到车道上方 → 吊架 → 带遮光罩和背板的灯箱；
行人灯直接夹在同一根杆上（距离 17cm），带红上绿下图标、走路帧、按钮盒和反光带；
车灯 10s 绿 / 3s 黄 / 13s 红，行人灯与之严格互锁。

**`addBox` 的 y 是底边，不是中心。** 灯面圆点若写在 `y = 0`，而灯箱本体从 `y = 0` 起、高 0.34，
圆心就会落在箱体下沿外面，看起来像"灯和红绿灯脱开了"。现在灯面固定在箱体中心，
灯箱顶盖与横臂之间还有吊架，距离关系由常量统一约束。

**新建的网格要立刻初始化到"零状态"。** 积雪薄板的几何体原始高度是 1（米），
不在创建时 `apply(0)`，在第一次 `update()` 之前它就是满厚度 —— 表现为"雨天屋顶和地面也是白的"。

**动态网格要排除静态合并。** 积雪用的是 `MeshToonMaterial`，正好会被 `mergeStaticMeshes`
并入 `merged-static` 并从原组摘除，于是 `snow-layer.children.length` 变成 0、动画完全失效。

**台面设备的排布要从"总长"反推，不能逐个写死。** 收银台上四件设备沿 x 依次排开，
间距 0.78 / 0.72 / 0.68，合计需要 2.92m，而台面只有 2.4m —— 最左边的热食柜整个悬在台外，
从街上隔着玻璃看就是"咖啡机左边浮着一块米黄方块"。这类问题的特点是
**每一件单独看都合理，只有算总和才暴露**。

**滑门不能有横穿门洞的静止构件。** 踢脚板、磨砂贴膜、中横梁、下沿收边原来都是整条通长，
门扇一滑开它们仍留在原地：0.4m 高的踢脚板像一道门槛，磨砂膜像一块不会动的门板。
现在所有沿前脸的通长构件都通过 `store.ts` 的 `frontGaps()` 在门洞处断开，开门后门洞是真的通透。

## 部署到 GitHub Pages

项目已经带了 GitHub Actions 工作流：`.github/workflows/deploy.yml`。
把 **本目录 `konbini-diorama/` 作为仓库根目录** 推上 GitHub，之后每次 push 到 `main`
都会自动 build 并部署。

### 1. 创建空的 GitHub 仓库

在 GitHub 上 New repository，仓库名例如 `konbini-diorama`。
**不要**勾选 Add a README / .gitignore / license，保持空仓库，避免第一次 push 冲突。

### 2. 本地初始化 Git 并推送

在 `konbini-diorama/` 目录执行：

```bash
git init
git add .
git commit -m "feat: konbini diorama"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

第一次 push 需要认证：

- **HTTPS + Personal Access Token**：GitHub → Settings → Developer settings →
  Personal access tokens；给 `repo` 权限（或 fine-grained 的 Contents: Read and write）。
  push 时用户名填 GitHub 用户名，密码填 token（不是账号密码）。
- **SSH**（推荐长期使用）：
  ```bash
  ssh-keygen -t ed25519 -C "你的邮箱"
  # 把 ~/.ssh/id_ed25519.pub 的内容加到 GitHub → Settings → SSH and GPG keys
  ssh -T git@github.com
  git remote set-url origin git@github.com:<用户名>/<仓库名>.git
  ```

如果还没配置提交身份：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

### 3. 开启 GitHub Pages

进入仓库 **Settings → Pages → Build and deployment**：

- **Source** 选择 **GitHub Actions**（不要选 Deploy from a branch）
- 保存后，push 会自动触发 `Deploy to GitHub Pages` 工作流
- 在仓库 **Actions** 页可以看到 build / deploy 进度

部署完成后地址是：

```
https://<你的用户名>.github.io/<仓库名>/
```

例如 `https://alice.github.io/konbini-diorama/`。

### 4. 更新页面

以后改完代码只需要：

```bash
git add -A
git commit -m "update scene"
git push
```

Actions 会自动重新构建部署，通常 1–3 分钟生效。

### 为什么不会出现资源 404

Vite 配置里已经写了：

```ts
base: './'
```

GitHub Pages 的项目页地址是 `/<仓库名>/`，如果用默认的 `base: '/'`，`/assets/*.js`
会指向域名根目录而不是仓库子目录，页面会空白。相对 base 同时兼容：

- 项目页 `https://user.github.io/repo/`
- 用户主页 `https://user.github.io/`

URL 参数也照常可用，例如：

```
https://<用户名>.github.io/<仓库名>/?time=day&weather=snow
```

### 常见问题

| 现象 | 原因 |
| --- | --- |
| Actions 报 Pages 相关错误 | Settings → Pages 的 Source 没选 GitHub Actions |
| 页面空白、控制台 assets 404 | `vite.config.ts` 的 `base` 被改成了 `/`；改回 `./` |
| `npm ci` 失败 | 仓库里缺少 `package-lock.json`；确认它被提交 |
| 私有仓库 Pages 打不开 | 免费账号的 Pages 需要公开仓库（或 GitHub Pro） |
| 第一次部署很慢 | Pages 首次构建/分配域名通常 1–3 分钟 |

> 如果以后把仓库根目录改成上一层工作区（包含多个项目），
> 需要把 workflow 里的 `run: npm ci` / `run: npm run build` 加上
> `working-directory: konbini-diorama`，并把 `upload-pages-artifact` 的
> `path` 改成 `konbini-diorama/dist`。当前配置默认仓库根就是本目录。

## 已知限制

- **玻璃不做真实折射**，只是低不透明度 + 雨痕叠加。三渲二不需要折射，要的是"能一眼看透店内"。
- **湿地反射是画上去的**（加色贴图），不是实时平面反射。更接近动画背景美术的观感，也更便宜。
- **静态合并后单件不可编辑**。若需要单独调某个零件，把它的 `name` 加进 `mergeStaticMeshes` 的 `excludeNames`。
- **UI 只有底部一块控制台**，没有加载页、没有设置面板；竖屏首屏会按宽高比自动退远，之后交给用户自己缩放。
- **晴天不会有"实心阴影"**：三渲二的阴影只是压暗一个色阶，晴天阳光的强投影感会偏弱。
- 首帧在低端设备上可能有 200–400 ms 的着色器编译停顿。
